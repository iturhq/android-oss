= UC-07: Start an activity — sign-in required for anonymous user
:icons: font

[cols="1,3"]
|===
| ID | UC-07
| Path type | Access boundary
| Feature | xref:../features.adoc#_feature_3_organise_an_activity[Feature 3 — Organise an activity]
|===

== Preconditions

* App is in the Idle state with an anonymous user.

== Steps

. Observe the Idle overlay.
. Verify *Sign in* and *Join an activity* are available.
. Verify *Start an activity* is not available.
. Sign in and observe the Idle overlay again.

== Expected result

* Anonymous users cannot initiate activity creation.
* After sign-in, *Start an activity* appears.
* No implicit sign-in or activity creation starts from the anonymous state.

== Reconciliation

An older draft described a Start button that opened a sign-in prompt for
anonymous users. The accepted UI implemented and verified by AOSS-45FE
instead hides Start until sign-in. This use case records that stable access
boundary rather than retaining an unimplemented dialog as normative
behavior.
