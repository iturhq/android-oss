= Coverage improvement plan

This plan raises production line coverage to at least 90% without hiding behaviour that can fail
in production. Defensive branches, exception mapping, dependency-injection wiring, Android
lifecycle handling, and real UI behaviour remain in scope.

== Coverage contract

Included:: All handwritten production code under `src/main`, `src/local`, and `src/prod`,
including defensive and failure paths.
Excluded:: Generated Hilt/KSP sources, Compose preview wrapper functions, debug-only test
activities, and `core:data-fake` test infrastructure.
Primary gate:: 90% line coverage across the included scope.
Secondary gate:: Branch coverage is reported and ratcheted independently; line coverage must not
be raised by suppressing reachable branches.

== Active tasks

=== COV-01: Make the coverage scope explicit

Status:: Complete
Started:: 2026-09-13

* Mark every Compose preview wrapper with `@GeneratedPreview`, which JaCoCo recognizes as
  generated while leaving the production composables called by the preview in scope.
* Ignore debug-only and generated paths in Codecov.
* Run `core:data-fake` tests without uploading the module as production coverage.
* Disable Codecov's implicit report search so only declared reports affect the badge.

Acceptance criteria:: JaCoCo omits preview wrapper methods; Codecov cannot ingest generated,
debug-only, or fake-repository files; defensive exception branches remain visible as uncovered.

=== COV-02: Report every unit-tested production module

Status:: In progress
Started:: 2026-09-13

* Enable unit-test coverage for `core:data-api`, `core:data-firebase`, `core:domain`,
  `core:location`, `core:model`, and `core:ui`.
* Generate and explicitly upload each module's XML report.
* Publish a deterministic aggregate summary and fail if an expected report is absent.
* Keep flavor-specific implementations distinct without double-counting shared sources.

Acceptance criteria:: The badge includes every production module with unit tests and the same
inputs can be reproduced locally with one Gradle command.

=== COV-03: Merge Android instrumented coverage

Status:: In progress
Started:: 2026-09-13

* Enable Android-test coverage for `feature:map` and `core:datastore`.
* Enable multidex for the datastore test APK; coverage instrumentation currently raises it above
  the 65,536-method limit.
* Preserve Test Orchestrator isolation for the map suite and collect its per-test `.ec` files.
* Merge unit and device execution data into the reports uploaded for the same commit.

Acceptance criteria:: All 59 map and 3 datastore device tests pass in coverage mode; their lines
appear in Codecov; no test is made order-dependent to obtain coverage.

=== COV-04: Cover persistence, backend, and authentication failure paths

Status:: Started
Started:: 2026-09-13

* Cover the remaining `AndroidKeystoreEmailCipher` key, corruption, and migration branches.
* Cover Firebase transaction failures, DTO conversion failures, and admission conflicts.
* Cover authentication cancellation, invalid credentials, configuration failures, initial auth
  state failures, sign-out failures, and user lookup failures.
* Add explicit assertions for the public error or recovery behaviour of every caught exception.

Acceptance criteria:: `core:auth`, `core:data-api`, `core:data-firebase`, and `core:datastore` each
reach at least 90% line coverage, with defensive branches tested rather than excluded.

=== COV-05: Cover map state, Compose surfaces, and MapLibre integration

Status:: Started
Started:: 2026-09-13

* Capture the coverage already exercised by the device suite before adding cases.
* Complete the `MapViewModel` state and failure matrix.
* Test idle, ongoing, blocking, error, help, QR, transient-surface, and effect behaviour with
  Compose tests.
* Extract MapLibre marker, camera, lifecycle, and style decisions behind testable adapters while
  retaining device tests for the real SDK boundary.

Acceptance criteria:: `feature:map` reaches at least 90% line coverage without excluding a
handwritten screen, callback, or failure branch.

=== COV-06: Cover shared UI and application wiring

Status:: Started
Started:: 2026-09-13

* Add light, dark, and dynamic-color theme tests.
* Test shared buttons, backgrounds, progress indicators, icons, and accessibility semantics.
* Add application navigation, observability initialization, and lifecycle smoke tests.
* Exercise handwritten Hilt modules through graph or provider tests.

Acceptance criteria:: `core:ui` and `app` each reach at least 90% line coverage; preview wrappers
remain the only handwritten UI exclusions.

=== COV-07: Ratchet and enforce the target

Status:: Started
Started:: 2026-09-13

* Set patch coverage to 90% with zero tolerance immediately after complete reporting lands.
* Ratchet project coverage through 50%, 70%, 80%, and 90% as the preceding tasks merge.
* Finish with a 90% project target and zero tolerance.
* Report branches separately so a line-only gain cannot conceal untested decisions.
* After the 90% gate is stable, continue toward 100% wherever behaviour is reachable; add no
  further exclusions without explicit agreement.

Acceptance criteria:: CI blocks a patch below 90% and blocks project coverage below 90%; all
coverage inputs and exclusions are explicit and version-controlled.

== Execution order

`COV-01` is complete. `COV-02` and `COV-03` establish the trustworthy baseline and run in
parallel. `COV-04`, `COV-05`, and `COV-06` use that baseline to close module gaps. `COV-07`
ratchets continuously and installs the final gate after every included module reaches the target.
